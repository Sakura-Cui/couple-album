# 简历与面试介绍

## 一句话

**Couple Album：基于 Kotlin / Jetpack Compose 与 FastAPI 的 Android 情侣私密相册，实现原片管理、并发断点续传、Live Photo、鉴权媒体播放与场景化加载动画。**

**Couple Album｜Android 情侣私密相册**  
技术栈：Kotlin、Jetpack Compose、Coroutines、OkHttp、Media3、Lottie、FastAPI、SQLite、FFmpeg、Docker。

- 围绕双人共享场景设计相册、设备邀请、密码保护、图文收件箱与媒体管理，支持置顶排序、批量移动/删除和后台重锁。
- 实现分片续传与任务持久化，采用 1 MiB 分片、3 路并发和连续确认窗口，区分发送进度与服务端恢复 offset，并通过 SHA-256 与原子落盘保证上传完整性。
- 处理 Live Photo 元数据配对、分组分页、方向与按住播放，结合完整加密缓存、播放器状态及首帧控制改善加载状态一致性。
- 集成 Media3、鉴权 Range 与独立 FFmpeg 播放副本；设计四种与业务状态联动的 Lottie 加载动画，区分传输完成与业务成功。

仓库：<https://github.com/Sakura-Cui/couple-album>

## 面试可以展开的点

1. **上传进度为什么不能直接用于续传？** 已发送不等于服务端连续持久化；并发乱序、响应丢失和重试会放大差异。结合 upload_parts、offset 和 displayOffset 解释。
2. **为什么实况不能只按照片/MOV 同名配对？** 文件名可重复或改名，需读 Apple ContentIdentifier，并控制相册归属、方向与分组分页。
3. **为什么 loading 到 100% 还不能播放成功动画？** 后续可能仍在哈希校验、保存、播放器准备或首帧显示；成功由业务状态触发。
4. **私密相册的权限在哪里保证？** 后端在相册、媒体、Range、缩略图和上传操作校验；前端隐藏与手机缓存加密不能替代服务端权限。
5. **为什么原片与兼容副本分开？** 原片保真和跨设备播放是不同需求；副本异步生成、状态独立，并沿用访问控制。
6. **当前方案的规模边界？** 单空间、最多三台设备、单机 SQLite/磁盘。没有多租户、高并发或跨地域可用性的未验证承诺。
